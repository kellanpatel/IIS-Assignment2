Project explanation:

What it is: 
A phone recommendation interface that heklps users jduge recommendations through explanations, visible trade-offs and missing-informaiton warnings.
It takes someones requirements, conpares with the phones' attributes, ranks suitable options then explains the results. Users always have control as they can inspect alterbative options and change their requirements to see how the recommendations change.

Design choices to explain:
Visible requirements: Users can see their requirements and how they affect the recommendations. They can also change them to see how the recommendations change.
Brief summaries followed by inspection: users can access detail without every result becoming a long explanation.
Matches alongside drawbacks: explanations provide grounds for judgement rather than only reasons to accept.
Explicit unknown information: the interface avoids presenting incomplete evidence as certainty.
Editable priorities and change feedback: users can see how their action affects the recommendations.
Final user choice: the system proposes options while the user decides.
